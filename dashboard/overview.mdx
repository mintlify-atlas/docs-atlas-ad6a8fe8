The GeoMine NWIS (Nearby Wells Intelligence System) dashboard is an industrial SCADA-grade interface for real-time drilling risk monitoring across the Assam Shelf basin. Built on Streamlit with a dark-themed, instrument-panel aesthetic, it fuses live rig telemetry, geospatial offset well analytics, ML-based risk scoring, and Gemini AI explanations into a single unified operational view. Every component refreshes from the active well's session state, ensuring drillers, engineers, and toolpushers always see a consistent, synchronized picture of the wellbore corridor.

---

## Five Dashboard Tabs

The main content area is divided into five tabs, each scoped to a distinct operational function. Navigate between them by clicking the tab headers at the top of the main panel.

<Steps>

  <Step title="GIS Spatial Command">
    An interactive map rendering the active rig position, a configurable search radius circle, and all nearby offset wells color-coded by historical incident type. A **Top Analog Offset Matches** panel to the right of the map ranks the top 4 most similar offset wells by similarity score, showing distance, formation zone, event type, event depth, and engineering notes. This is the primary spatial situational awareness screen.
  </Step>

  <Step title="Offset Records & Deep-Dive">
    A sortable, interactive well intelligence table listing every offset analog within the current search corridor. Columns include analog similarity (rendered as a progress bar), well name, well ID, distance, formation zone, historical incident type, and incident depth. Clicking any row opens a **Deep-Diver** panel below the table: four metric cards (distance, match score, incident depth, incident classification), a standard mitigation guidance block, and a depth proximity radar visualizing the current bit position relative to the historical incident depth. A CSV export button generates a structured handover report for shift changeovers.
  </Step>

  <Step title="Offset Trends & Analytics">
    Two Altair charts summarizing offset well patterns across the active search corridor. A horizontal bar chart ranks every retrieved analog well by similarity score, color-coded by incident type. A column chart displays the corridor incident hazard breakdown — the count of wells by incident classification (Stuck Pipe, Mud Loss, Torque Spike, None). A statistical summary card below the charts reports total analogs analyzed, stuck-pipe count, mud loss count, torque spike anomalies, and clean uneventful wells.
  </Step>

  <Step title="Live Telemetry & Safe Envelopes">
    Five live metric readouts (ROP, RPM, Torque, WOB, MSE) sourced from the current session telemetry state. A dedicated **Teale's Mechanical Specific Energy (MSE)** analyzer card computes the Teale formula in real time and displays a status badge (Optimal/Elevated/Critical Pack-Off). Below that, four operating envelope gauge cards compare the live sensor values against the configured `TELEMETRY_THRESHOLDS` safe ranges, rendering color-coded status badges and progress bars for ROP, Torque, RPM, and WOB.
  </Step>

  <Step title="Searchable Knowledge Repository">
    A natural language search interface powered by Gemini NLP and RAG (Retrieval-Augmented Generation). Engineers type free-form queries about historical drilling events; the backend parses the query, performs hybrid vector and keyword search over the PostgreSQL knowledge base, and returns evidence-ranked incident records. Each result card is expandable and shows root cause, mitigation, and outcome. An optional **Historical Inference** section summarizes patterns across the full result set. The tab also provides an **Automated Document Ingestion** expander for pasting raw DDR/completion report text, which Gemini structures and appends to the knowledge base.
  </Step>

</Steps>

## SCADA KPI Cards

Immediately below the brand header, five industrial instrument panels provide an at-a-glance operational status read. These cards update every time a new analysis is run or the live simulator ticks.

| Instrument Panel | Tag | What It Shows |
|---|---|---|
| **TAG: WELLBORE** | Active wellbore identifier | Active well name and field, e.g. `DLJ-47A` — Duliajan, Assam Shelf |
| **MEASURED DEPTH** | BIT MD | Current bit depth in metres, planned total depth (TD), and metres remaining to TD |
| **CORRIDOR HAZARD** | Risk score 0–99 + level badge | ML risk score (0–100) and risk level: `IDLE`, `LOW`, `MEDIUM`, `HIGH`, or `CRITICAL`. Footer shows the predicted event type |
| **OFFSET ANALOGS** | Analog count + radius | Count of nearby wells found within the active search radius (km) and depth corridor (±m). Shows formation zone when wells are present |
| **STUCK-PIPE EVENTS** | Incident counts | Stuck-pipe incident count with `ELEVATED` / `NORMAL` badge. Footer shows Mud Loss and Torque Spike counts |

The corridor hazard card changes color dynamically: green for LOW, yellow for MEDIUM, orange for HIGH, and red for CRITICAL.

## Operational Directive Banner

Directly below the KPI cards, a full-width banner communicates the active operational directive derived from the risk assessment. The banner color adapts to the current risk level:

| Risk Level | Banner Color | Border |
|---|---|---|
| `LOW` | Dark green | `#22c55e` |
| `MEDIUM` | Dark amber | `#eab308` |
| `HIGH` | Dark orange | `#f97316` |
| `CRITICAL` | Dark red | `#ef4444` |

The banner contains three content zones:

- **OPERATIONAL DIRECTIVE** — the risk level and predicted event type in the title, e.g. `⚠ OPERATIONAL DIRECTIVE — HIGH HAZARD (STUCK PIPE / MUD LOSS)`.
- **Recommended Action** — a plain-language operational instruction derived from the historical incident density in the offset corridor, e.g. *"Maintain steady drill string rotation, monitor cuttings return, and review mud weight."*
- **Explainability Factors** — the evidence string (either from the historical context or Gemini AI, if the AI toggle was enabled) plus a corridor incident tally: Stuck Pipe, Mud Loss, Torque Spike counts.

When an AI summary is pending (lazy-loading in progress), the evidence zone shows *"Gemini AI is analyzing offset wells..."* until the LLM result arrives and replaces it in place.

## Live Rig Simulator

The sidebar exposes a **Real-Time eRTMAC Simulator** toggle beneath the main analysis form. Activating it starts an autonomous physics-driven simulation loop that advances the bit depth at approximately 1 tick per second and drives all four telemetry channels through lithology-based zones.

| Depth Range (m) | Physics Zone | Behavior |
|---|---|---|
| 2,480 – 2,550 | **Normal Shale** | Smooth drilling: WOB ≈ 8.5 klbs, RPM ≈ 125, Torque ≈ 3,200 ft-lbs, ROP ≈ 22 m/hr |
| 2,550 – 2,620 | **Hard Sandstone Stringers** | High WOB, elevated torque, low ROP: WOB ≈ 16.5, RPM ≈ 90, Torque ≈ 4,800+, ROP ≈ 8.5 |
| 2,620 – 2,680 | **Fractured Fault Zone** | Erratic stick-slip: random torque spikes between 2,500 and 6,200 ft-lbs, RPM oscillates ±40 |
| 2,680 – 2,750 | **Washout / Cavings** | Low bit contact: WOB ≈ 2.5, RPM ≈ 140, Torque ≈ 1,800, ROP ≈ 28 |

When the simulator reaches 2,750 m it resets to 2,480 m for a continuous demo loop. All telemetry channels apply a random walk smoothing toward their zone targets (with ±noise) to produce realistic gauge movement. The simulator calls `analyze_drilling_risk` on every tick and writes results into `st.session_state`, triggering `st.rerun()` to refresh the dashboard. Gemini AI summaries are intentionally suppressed during simulation to prevent LLM rate limiting.

<Note>
Activating the simulator automatically sets the **Radial Search Buffer** to 45 km to ensure offset wells are visible at all simulated depths.
</Note>

## Data Modes

The dashboard data layer is configured via the `DATA_MODE` environment variable in `config.py`. Three modes are supported:

```bash
# Use the built-in in-memory well records from wells_data.py (default)
DATA_MODE=local

# Load well records from a CSV file named wells.csv in the working directory
DATA_MODE=csv

# Connect to the PostgreSQL instance configured via PG_* env vars
DATA_MODE=postgres
```

The backend API URL is set via `BACKEND_URL` (default: `http://backend:8000`). All analysis requests POST to `{BACKEND_URL}/api/analyze_risk`. In `local` mode the dashboard can compute offline risk scores using the built-in GIS engine and `wells_data.py` records without hitting the backend.

```bash
# Override the backend endpoint at runtime
BACKEND_URL=https://your-backend-host.example.com
```

<Warning>
If `DATA_MODE=postgres` is selected but the PostgreSQL credentials (`PG_HOST`, `PG_PORT`, `PG_DATABASE`, `PG_USER`, `PG_PASSWORD`) are not configured, the repository stub falls back to the local in-memory `WELLS` list. Confirm database connectivity before deploying to production.
</Warning>
